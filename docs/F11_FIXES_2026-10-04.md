## 1. Mount points (`b7ae356`) — closes the CLAUDE.md leftover

**Symptom:** 10 lines of `Obsolete default definition of mount points in
MyObjectBuilder_UpgradeModule/GT_…` on every load, one per block. They come from all
4 Radiation Monitors, all 4 Weather Stations, `GT_BioScanner` and `GT_BioScanner_S`.
All 10 had an empty `<MountPoints>` tag, so the engine also fell back to full-face
mounts on all six sides.

**Fix:** one `<MountPoint>` per block on its single base face, full face
(`0.00..1.00`). The sides come from MTGraves' own definitions for the same `.mwm`
files in the Naval Theme Prop Pack (2494017078). They were not guessed from the model.

- `Side="Bottom"`: both Radiation Monitor shapes (dome and tall scanner),
  `GT_WeatherStation(_S)`, `GT_BioScanner(_S)`
- `Side="Back"`: `GT_WeatherStationAlt(_S)`, the wall-mounted rotating sensor

MTGraves gives the large 1x1x1 Bottom faces `EndY="2"`. That is an overshoot on a
1-deep face, and we use `1.00`. His `ExclusionMask`/`PropertiesMask` were not carried
over, to match this file's existing style.

**Gotcha if you edit the SBC:** its lines end in `\r\r\n`, not CRLF. Tools that
normalise line endings will rewrite every line of the file. Keep the diff minimal.

**Player-facing consequence:** instruments that players had already placed
sideways could detach on update. Jason announced it in the Workshop comment.

## 2. Script logic collision notices (`8152c82`)

**Symptom:** 4 × `mod_notice … Possible entity type script logic collision`.

**Cause:** the four Weather Station subtypes each had two game logic descriptors,
`InstrumentPower` and `SpinningInstrument`. The engine wraps the pair in a composite
component and logs one notice per subtype. It worked, but it was noise.

**Fix: one game logic component per subtype.**

- `Rotation.cs`: `SpinningSubpart` (an abstract `MyGameLogicComponent`) and
  `SpinningInstrument` are **gone**. In their place is `SubpartSpinner`, a sealed
  plain class:
  - `SubpartSpinner.TryCreate(IMyEntity, string subpartName)` returns null on a
    dedicated server, when no subpart is named, or when the grid has no physics.
  - `Tick()` holds the old per-frame body, moved across unchanged: speed, accel and
    decel, the 1 km camera cull, the cached local matrix.
  - If it throws, it sets `_failed` and stops itself. It no longer clears its
    host's `NeedsUpdate`, because the host is now `InstrumentPower` and must keep its
    power sink.
- `SpinningAntenna` **still exists under the same name** and keeps its own
  `RadioAntenna` descriptor for `GT_RotatingRadarDish(_S)`, since nothing else binds
  the dish. It is now a thin `MyGameLogicComponent` that owns a `SubpartSpinner`.
  `TACTICAL_PLAN.md` D0.4 ("the dish's rotation is decoration and stays exactly as it
  is") still holds in behaviour. The class's internals changed, though. **If Phase 1
  adds a second descriptor on the dish subtypes, the collision notice comes back.**
  Put any dish game logic in `SpinningAntenna`, or move the spinner into whatever new
  component owns the dish, the way `InstrumentPower` now owns it for instruments.
- `InstrumentPower.cs` gained a `_spinner` field. At the end of the
  `UpdateOnceBeforeFrame` comment block, just before the `_megawatts <= 0f` early
  return, it now does `Instruments.TryGet` and then `SubpartSpinner.TryCreate`. When
  that returns a spinner it sets `NeedsUpdate |= EACH_FRAME`. A new
  `UpdateBeforeSimulation` calls `_spinner.Tick()`. Nothing else in the file changed:
  sink, `SealSync`, the CustomData handshake and `Close` are as they were.
- Only the 4 Weather Stations have a `Subpart` in the `Instruments` table, so the
  set of spinning blocks is unchanged.

**Known edge, not hit today:** `InstrumentPower.Init` returns before scheduling
`UpdateOnceBeforeFrame` when an instrument's power is ≤ 0. A future 0 kW instrument
with a spinning subpart would therefore not spin. The Weather Stations draw 15 kW.
